# Tracking Cloth physical-action feasibility v1

## Question

Can the public Tracking Cloth self-collision factorial support a genuine
act--sense--fallback experiment in which the terminal alternatives are physical
interaction configurations rather than estimator corrections?

The dataset contains four materials, three physically executed release
configurations, and three repetitions. Every material/repetition block therefore
contains a complete three-action outcome vector. This audit opens repetitions 1
and 2 only and keeps repetition 3 numerically closed.

## Source-only task

The physical actions are:

1. `four_corners_normal`;
2. `four_corners_parallel`; and
3. `two_corners_normal`.

For each action, the source task loss combines two quantities over the 3 s
post-prefix trajectory:

```text
task_loss = normalized_self_contact_depth_rms
            + 0.25 * 95th_percentile_absolute_grid_edge_strain
```

Non-neighbor marker pairs exclude the local 5 x 4 cloth-grid neighborhood.
After the complete initialization frame, isolated missing marker coordinates are
filled causally from the last observation and the pre-fill missing fraction is
reported. The loss is intended as a transparent deformation/contact-risk
objective, not as a claim that the dataset authors registered this control task.

## Resettable probe feasibility

Each physical interaction supplies a 0.5 s prefix. For each interaction, the
probe feature is the RMS change in all pairwise cloth-marker distances from the
first to the final prefix sample, normalized by initial cloth diameter. A binary
source-only threshold is the midpoint between the two central values across the
eight material/repetition source blocks. A constant source feature remains a
one-outcome, uninformative probe; the audit never invents a binary split from
file or row order.

The audit treats a prefix under one interaction as a **resettable diagnostic
probe** followed by a separately executed terminal interaction. This is a
block-level feasibility model. It does not establish that the public recordings
were generated by a sequential probe/reset/action protocol or that reset error
is negligible.

For every material, the quotient places all mass on that material class while
leaving its two source repetitions unresolved. The exact act--sense--fallback
certificate evaluates the three direct actions and all binary probe-contingent
action maps over a fixed grid of probe costs and regret tolerances.

## Promotion rule

A fresh rep3 protocol is only worth separate review when all three source
conditions hold:

- at least two different physical actions are source-optimal;
- at least two materials have the same source-optimal action on rep1 and rep2;
- at least one source setting uses a decision probe and improves over the fixed
  source fallback.

This file does not authorize rep3 access. Even a positive source audit requires
a new content-addressed protocol, explicit reset interpretation, frozen task
loss, and one-shot rep3 prediction seal before target outcomes are opened.

## Run

```bash
python -m experiments.tracking_cloth_action_feasibility_v1.run \
  --dataset-root /path/to/tracking-cloth-deformation-v1 \
  --output /tmp/tracking-cloth-action-feasibility-v1
```

The permanent workflow runs synthetic contract tests on GitHub-hosted workers.
Only a push to `main` may execute the source-only data audit on
`[self-hosted, Linux, X64, gpuserver4090]`. The artifact contains compact JSON,
CSV, and Markdown evidence, never raw trajectories.

## Claim boundary

This is source-only feasibility evidence. It does not establish a held-out
physical-action benefit, online sensing, reset fidelity, unseen-material
transfer, calibrated action loss, closed-loop robot control, deployment safety,
or state of the art. Rep3 numerical outcomes remain unopened.
