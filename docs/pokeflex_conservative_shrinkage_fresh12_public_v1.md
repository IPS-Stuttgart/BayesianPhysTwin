# PokeFlex Fresh-Take Checkpoint Comparison V1

## Question

Does the unchanged, source-selected Bayesian correction improve the released
PokeFlex Kinect checkpoint on public recordings that were not used in any
tracked or server-side PokeFlex experiment?

This is the strongest public test that remains available without the five
official validation archives that are absent from the public release. It is a
paired released-checkpoint comparison, not a reproduction of the published
18-take table.

## Cohort lock

The target-free audit found 116 public poking archives. Eighty-four take IDs had
already appeared in tracked PokeFlex branches or in metadata-only scans of the
two GPU servers. The 32 remaining archives cover 12 physical objects. For each
object, the protocol chooses the take with the smallest SHA-256 of
`pokeflex-fresh12-selection-v1`, a NUL byte, and the take ID.

The exact exclusion evidence, inventory digests, selected take IDs, and source
ZIP hashes are bound by
`configs/sota/pokeflex_fresh12_exclusion_audit_v1.json`. Other recordings of
the same physical objects were used during source development. Therefore the
claim is prospective new-take transfer, not unseen-object transfer.

A pre-outcome storage amendment permits opaque extraction of only robot data,
Kinect calibration/depth, and mesh OBJ bytes on the source server. A canonical
stage manifest binds the original ZIP hash and every transferred member. Mesh
geometry remains undecoded and unscored until the all-case barrier; this changes
storage provenance, not the cohort or method.

## Frozen method

The method remains
`checkpoint_action_local_state_relative_0.4_residual_scale_0.125`, selected by
the existing nine-object source gate. It uses Kinect frames `f-5` through
`f-1`, measured robot history through `f-1`, and a graph registration update at
`f-1` to predict frame `f`. Missing action history, failed registration, or
unsupported action produces the released checkpoint output byte for byte.

No parameter, selector, support threshold, or scale is re-estimated on this
cohort.

## Custody and gates

All 12 predictions must be generated by one clean implementation revision and
sealed before any scored target mesh is opened. There is no replacement after
technical failure.

The primary gate requires all of the following on the 12 physical-object
means:

- positive object-balanced CD-UL1 improvement over the released checkpoint;
- a 97.5% paired object-bootstrap upper bound below zero millimetres;
- no per-object regression;
- exact checkpoint fallback on every unsupported frame.

The published 6.498 mm result is contextual only because this cohort is not the
published validation split. Jaccard remains non-gating because released target
meshes are not guaranteed to support the published volumetric Boolean
operation.

## Causal boundary

Target-frame RGB-D, robot state, and deformed meshes are forbidden prediction
inputs. The template mesh remains an explicit input, matching the released
PokeFlex reconstruction setup. Outcome access begins only after the all-case
prediction barrier validates.

No held-v8 artifact or process is part of this protocol.
