# Deform360 tactile-guard outcome-sealed transfer v1

## Purpose

This protocol tests whether the source-fitted causal tactile regret guard
transfers beyond the opened Open27 and stress12 development panels. It does
not claim fresh physical-object identities. The public Deform360 catalog is
exhausted under the conservative union of objects already opened, selected,
reserved, or technically dispositioned by prior studies.

The evaluation population is instead the twelve V14 source cases whose
prefixes and physical carriers were processed while their future outcomes
remained sealed. The registered claim label is:

```text
prospective_outcome_sealed_identity_known_transfer
```

This can establish prospective transfer to untouched outcomes on a
pre-identified cohort. It is not fresh-object confirmation and is not, by
itself, a state-of-the-art claim.

## Frozen method

At update frames 19, 38, and 57:

1. The current causal multiview observation selects the physical or
   persistence backbone. Insufficient support defaults to persistence.
2. The frozen pairwise-consensus gate either updates the recursive RBF belief
   or preserves the selected backbone exactly.
3. Raw baseline-subtracted tactile features use only values available through
   the current update. No episode-wide peak normalization is allowed.
4. The frozen tactile score admits or rejects the candidate interval.
   Rejection is bit-exact selected-backbone fallback.

The physical and persistence trajectories come from each case's already
sealed V14 Warp carrier. Known future robot action is allowed; future object
RGB, geometry, tracks, identities, tactile values, and metrics are not.

## Failure accounting

Every locked case must receive exactly one disposition before any future is
opened:

- ordinary successful prediction;
- retained technical failure with bit-exact persistence fallback; or
- unsealable case.

The barrier reports those three counts plus the total locked count. Technical
failures remain in the denominator and cases are never replaced. An
unsealable case blocks the barrier and therefore blocks all outcome opening.
A retained technical fallback is reported separately from an ordinary model
prediction even though it provides a valid operational output.

## Advancement gates

The outcome-sealed transfer passes only if all registered gates pass:

- at least two cases improve both hidden identity RMSE and hidden Chamfer;
- no case regresses on both metrics;
- object-balanced hidden identity RMSE improves by at least 1%;
- object-balanced hidden Chamfer improves by at least 1%;
- the object-cluster bootstrap upper confidence bound is nonpositive for both
  primary differences.

Passing justifies a later independent confirmation on a genuinely new public
dataset or newly released Deform360 objects. Failing closes this tactile guard
without retuning it on the twelve opened outcomes.

## Required order

```text
validate V14 custody
-> stage and seal all twelve physical/persistence backbones
-> extract causal raw tactile features
-> build causal AllTracker prefix measurements
-> build guarded predictions or declared exact fallbacks
-> seal the all-case prediction barrier
-> only then authorize and materialize future outcomes
-> score once and report every locked case
```

The protocol does not read or modify held-v8 artifacts or processes. V14's
failed direct-depth method is not revived; only its still-sealed cohort and
already sealed physical carriers are reused as provenance-bound inputs.
