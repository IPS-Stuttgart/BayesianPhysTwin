# DLO-Lab wrapping native-Linux qualification v7

## Purpose

The corrected v6 gate sealed 22 fresh Python 3.11 constructor processes under
WSL and then encountered a native `SIGSEGV` inside Genesis `scene.build`.
Together with the earlier Python 3.12 failure, this closes a simple interpreter
version explanation but leaves the WSL/native-runtime boundary unresolved.

V7 changes exactly that boundary. It runs the unchanged v6 native adapter,
preflight world, action bank, process counts, and QA on the native Linux host
`workstation2`. It uses the same Python 3.11.15 executable bytes and package
versions. Public source, the portable OSMesa dependency closure, runtime lock,
kernel/host identity, and every implementation file are hash-bound.

## Frozen gate

The campaign runs 24 fresh-process constructor probes followed by four complete
2,200-microstep rollouts. Constructor probes require deferred material
randomization and finite state. Full rollouts require exact registered bending
and stretching after reset plus the unchanged v4 native QA.

The gate passes only with 24/24 and 4/4 ordinary successes. Any exception,
signal exit, missing seal, QA failure, host/runtime mismatch, or custody mismatch
is terminal. No retry, replacement, padding, or partial result is allowed.

## Evidence boundary

Only committed compact summaries from v4-v6 may be read. The runtime arrays,
logs, partial rewards, and crash cores from those campaigns are excluded. V7
defines no fresh scientific worlds and produces no accuracy, uncertainty,
safety, or SOTA result. A pass permits only a separately frozen scientific
study on native Linux.
