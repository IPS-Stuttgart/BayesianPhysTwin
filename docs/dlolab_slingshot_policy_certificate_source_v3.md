# DLO-Lab Slingshot independent-action policy certificate v3

## Question

Can the frozen posterior-aware policy-gain certificate improve expected
Slingshot reward over the incumbent while retaining a calibrated low harm rate
when every possible future action is evaluated through an independently
qualified native execution interface?

This is a prospective public-simulator source study. It uses no recording,
protected target, held-v8, DLO4, or DLO5 data. It is not an official benchmark,
SOTA, real-robot, or physical-safety experiment.

## What is unchanged

The v3 policy is not a new model selected after seeing v2 outcomes. It freezes
the same 147 opened source-training worlds, posterior-predictive mean action,
161-dimensional residual-independent competence feature, inverse-distance
seven-neighbor gain predictor, action bank, incumbent, 0.002 harm margin,
128-world conformal calibration arithmetic, simultaneous-regret comparator,
288-world evaluation size, bootstrap, and source gates used by v2.

The v2 roster remains closed. Its 286 successful futures are not scored, and
its two failed worlds are not retried or replaced.

## What changes

V3 uses new disjoint calibration and evaluation worlds and new sensor draws.
The only method change is the native execution surface qualified by the frozen
64-process development audit:

```text
one world + one action + one fresh Python process
```

All eight action slots must seal ordinarily and reassemble into one world that
passes the unchanged common-prefix, duplicate-action, fixed-endpoint, material,
placement, and reward checks. A world enters calibration or scoring only after
that complete qualification is reproduced.

Causal prefixes retain the already stable eight-world batch interface. They
contain only the first 300 native steps under the incumbent action, with no
reward, future, or hidden-state restart.

## Information order

1. Bind the committed implementation, parent evidence, qualification result,
   runtime, action bank, fresh rosters, and one-attempt ledger.
2. Generate all 128 calibration prefixes and seal candidate predictions.
3. Run 1,024 independent calibration action processes and qualify all 128
   complete worlds.
4. Seal the policy-gain and matched simultaneous-regret calibrators.
5. Generate all 288 evaluation prefixes and seal guarded decisions.
6. Require at least 24 accepted and 24 exact-fallback worlds before any
   evaluation action process starts.
7. Run 2,304 independent evaluation action processes, qualify all 288 worlds,
   and score once.

Every future process reproduces the applicable candidate or decision barrier
before its write-once claim. No future outcome can alter a candidate action,
calibrator, threshold, roster, or gate.

## Failure policy

There is one attempt and no replacement. A failed action, malformed seal,
failed world QA, or incomplete 288-world denominator is a retained technical
negative. No successful subset is scored. The run does not fall back to the
shared native execution interface and does not modify the registered method.

## Claim boundary

A passing source gate would establish a public-simulator, query-conditional
policy-value certificate for this registered Slingshot distribution. It would
not establish benchmark SOTA, real-world transfer, conditional coverage,
robot safety, or general simulator competence. A failed source gate remains a
valid negative and does not authorize post-outcome tuning on this roster.
