# Chronological broken-mechanism physicality certificate v2

## Purpose

`CrossActionPlaceboProtocolV2` is a target-closed supplement to the chronological
sparse-pair transport contract in `cross_action_transport_v2.py`. The parent
transport result asks whether a source-admitted guarded physical correction
improves a different held-out action relative to unchanged physics,
`last_residual`, and discrepancy-only persistence.

A positive parent result is predictive transport evidence, but it does not by
itself show that the gain depends on the claimed physical relation. Version 2
therefore asks the stronger question:

> Does the supported guarded physical prediction beat controls that preserve
> superficial prediction structure while deliberately breaking the registered
> source action, physical session, temporal alignment, or material identity?

This certificate is prospective analysis infrastructure. Green tests and a
sealed protocol are not physical evidence. The first claim-bearing result still
requires the frozen Causal4D acquisition and must be retained whether positive,
negative, parent-negative, or insufficient.

## Registered control family

The physicality family contains one exact copy of the guarded parent prediction
and exactly four broken-relation controls:

1. `wrong_source_action` uses a source-prefix donor whose registered action
   profile differs from the source action for the scored session.
2. `wrong_object_session` uses a source-prefix donor from another independent
   physical session while preserving the registered source action profile.
3. `phase_shifted_source` applies a preregistered nonzero temporal shift to the
   source evidence while preserving the target query.
4. `identity_permuted` applies a content-addressed non-identity material/graph
   permutation while preserving the tensor dimensions.

For every physical session, each concrete donor, shift, permutation, source
artifact, construction artifact, policy, and constructor revision must be
content-addressed and sealed before the target outcome is opened. The contract
rejects missing controls, reverse chronology, unregistered donors, zero phase
shifts, identity permutations, target-informed construction, and mixed software
revisions.

## Parent binding and chronology

The placebo protocol binds one exact `CrossActionProtocolV2`. A scored result
additionally binds one exact `CrossActionTransportResultV2`. Every physicality
prediction must preserve byte-for-byte:

- physical-session ID;
- source and target execution IDs;
- source and target action IDs;
- chronological `information_order_id`;
- guarded parent prediction ID and disposition;
- target outcome, target-access attestation, and scorer;
- prediction batch and BayesianPhysTwin revision; and
- the exact guarded-parent prediction artifact and score.

A reverse target-to-source construction therefore fails closed. Placebo rows
cannot introduce another target access boundary or a target-side challenger
selection.

## Exact fallback

When the guarded parent rejects its candidate, all five certificate arms must
select the same prediction artifact and receive the same proper score. The
session then contributes exactly zero to all four placebo contrasts. Rejected
updates cannot manufacture physicality evidence and do not count as accepted
physical sessions.

## Independent unit and simultaneous inference

The complete physical grasp session is the independent statistical unit. Frames,
time points, coordinates, action labels, contacts, donors, material nodes, and
posterior samples remain nested observations.

For lower-is-better score `S`, define for session `s` and placebo `p`

```text
C[s,p] = S[s,p] - S[s,guarded_physical].
```

Positive values favor the guarded physical prediction. Complete sessions are
resampled jointly across all four contrasts. The registered
`paired-session-max-deviation-bootstrap-v1` computes one familywise critical
value and simultaneous one-sided lower confidence bounds. Marginal intervals
may be reported descriptively, but only the simultaneous bounds enter the
claim-bearing decision.

## Decision rule

`physicality_supported` is returned only when all of the following hold:

1. the exact parent result is `physical_transport_supported`;
2. enough independent scored sessions remain;
3. every parent-scored session has all five registered arms exactly once;
4. at least one guarded physical update was actually accepted;
5. every fallback arm is artifact- and score-identical; and
6. every simultaneous placebo lower bound exceeds the frozen separation margin.

A tie or failure for any one placebo returns `physicality_not_supported`.
Parent failure and parent insufficiency are reported separately and cannot be
rescued by placebo behavior.

## Relationship to the three-repository evidence program

- **BayesianPhysTwin** owns the guarded physical candidate, exact fallback,
  chronological transport test, and this broken-mechanism certificate.
- **Causal4D** owns the 18-session/36-execution physical acquisition and its
  separate abduction--intervention--prediction claims. The acquisition schedule,

- **Prob4D** is not a new prerequisite. Any observation provider remains subject

## Before confirmatory execution 1

The final runtime certificate must be created only after the physical object,
source artifacts, query, scorer, candidate, guard, and software environment are
frozen. Before target access:

1. instantiate the exact parent chronological transport protocol;
2. construct all `18 x 4` broken-relation records from source-prefix information;
3. seal the guarded-parent and placebo prediction batch together;
4. verify adversarially that missing, duplicated, reversed, target-informed, or
   fallback-divergent records fail closed; and
5. retain the resulting positive, negative, parent-negative, or insufficient
   decision without reconstruction or threshold changes after target access.

## Claim boundary

A positive result supports bounded separation of the registered guarded physical
transport prediction from four deliberately broken physical relations on the
exact frozen Causal4D roster and software stack. It does not establish a unique
physical cause, arbitrary-action or unseen-object generalization, calibrated raw
covariance, real Prob4D provider competence, Causal4D intervention benefit,
deployment safety, or state of the art.
