# TAPNext++ Frame-Zero Material Transport Source Protocol

## Motivation

The prior eight-case sparse-assimilation study failed even though its tracker
provider was competent. Its post-open audit found that only 2 of 27 query
associations preserved the benchmark's fixed frame-zero material node.
Source-frame nearest geometry therefore attached most accurate observations to
the wrong physical identities.

This study tests the missing bridge without reusing those eight future
outcomes:

> Can a causal TAPNext++ observation remain attached to one immutable
> frame-zero PhysTwin node through the terminal training-prefix window?

## Source Panel

The panel contains all 14 released PhysTwin cases excluded from the failed
eight-case assimilation panel. Every fixed case remains in the accounting;
technical failures are not replaced. These cases are already-open source data,
so a positive result remains developmental rather than independent evidence.

## Frozen Provider

For each case:

1. use the terminal 20 frames ending exactly at the released training boundary;
2. select up to four manual material identities that are finite at frame zero
   and the query frame, using deterministic frame-zero farthest-point coverage;
3. bind each identity once to its nearest physical graph node at frame zero;
4. run the official TAPNext++ checkpoint causally on three calibrated RGB-D
   views;
5. preserve strict multiview rows and use the previously frozen single-camera
   RGB-D completion only after source-only camera competence passes; and
6. score the withheld 20-frame manual prefix only after both tracker and
   completion predictions are sealed.

Manual identity is used for source-study query initialization and material-node
binding. The study does not claim deployable automatic query selection.

## Prospective Assimilation

Provider success authorizes a separate future-prediction lock, not automatic
future scoring. The intended update is already fixed:

\[
e_{i,t}=
\left(y_{i,t}-y_{i,0}\right)
-
\left(x_{g(i),t}-x_{g(i),0}\right),
\]

where \(g(i)\) is the immutable frame-zero graph node. The query row anchors
the displacement and is not processed as an update. Covariance for each
relative row includes both endpoint and anchor covariance plus an isotropic
term from frame-zero point-to-node attachment distance. Reliability remains
independent of the physical innovation, which enters once through the robust
mixture likelihood.

The sparse posterior may be applied directly at fixed nodes or smoothed with
the same rank-free spring-graph prior and 10 mm cap used by the failed arm. No
graph strength, cap, tracker setting, or arm may be selected from the new
future outcomes.

## Provider Gate

The provider phase advances only if all registered aggregate gates pass:

- at least 10 of 14 cases pass their per-case provider gate;
- pooled support is at least 85%;
- case-balanced gain over exact persistence is at least 10%;
- case-balanced identity RMSE is at most 15 mm; and
- all 14 cases receive a recorded disposition.

Failure stops before future assimilation outcomes are opened. A pass permits a
new checksummed assimilation protocol binding the provider summary.

## Evidence Order

```text
implementation + provider protocol lock
-> source staging + immutable material attachments
-> strict TAPNext++ prediction seals
-> decoded RGB-D completion prediction seals
-> open withheld source-prefix identities
-> aggregate provider gate
-> only on a pass: freeze and seal future-assimilation predictions
```

## Boundary

The previous eight future outcomes cannot tune this method. The 14 source cases
cannot establish independent confirmation or a state-of-the-art claim. No
held-v8 runtime, target, query, score, barrier, or outcome artifact is
authorized while its independently owned calibration gate remains pending.
