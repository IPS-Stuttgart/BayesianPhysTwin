# Deform360 causal-support guard source result v1

## Status

This is post-open source-development evidence, not a prospective confirmation or
state-of-the-art result. It used 117 already-open update intervals from 17
physical objects and excluded each held object from threshold fitting.

The three-route union admitted a candidate through low tactile loading, a large
causal correction change, or temporal consistency with the previous belief.
Every rejected interval retained the selected physical/persistence baseline
exactly. Exact candidate no-ops were not counted as admissions.

## Result

| Source panel | Identity change | Chamfer change | Beneficial updates | Regressive updates |
| --- | ---: | ---: | ---: | ---: |
| Open27 | -5.92% | -4.88% | 11 | 0 |
| Stress12 | 0.00% | 0.00% | 0 | 0 |
| Combined | -4.76% | -3.95% | 11 | 0 |

The guard produced six joint case wins and no case regression. However, the 11
nontrivial admissions came from only four objects. The locked development check
required at least five objects with a nontrivial admission, so v1 did not
advance despite passing every accuracy and zero-regression check.

This distinction matters: seven objects had at least one route fire, but three
of those had an exact candidate no-op. They are support diagnostics, not method
wins, and are not counted as admissions.

## Interpretation

The result supports the union-guard idea but shows that the three routes remain
too narrow. It must not be repaired by weakening the breadth check or by
counting no-ops. A successor may add a separately named, physically motivated
route, but it remains source development and requires a genuinely fresh,
non-overlapping prospective evaluation before any confirmation claim.
